# 开源模块接入审计（2026-08-10）

## 结论

“代码中出现适配器”不等于“已经改善每次成片”。当前模块分为已进入生产链、已安装但仅部分使用、只有适配器、以及研究候选四类。

## 已进入生产链

- **FFmpeg / FFprobe**：实际负责镜头标准化、拼接、旁白、字幕、环境声、Logo、CTA、H.264/AAC与响度母版，是当前最成熟的交付模块。
- **OpenCV**：由视频抽帧与场景分析链路使用；本机GStreamer缺少QuickTime解复用插件时会回退到FFmpeg路径。
- **PySceneDetect**：检测一个生成镜头内部不应出现的硬切，实际进入连续性质检。
- **Ollama + Qwen3-VL**：用于素材分析、关键帧审核和视频抽帧审核；属于自动审核辅助，不代替人工终审。
- **Pillow**：负责参考图归一化、关键帧画布、CTA与后期图形资产。

## 已安装但仅部分进入生产链

- **Video Shotcraft**：镜头卡目录、原则摘要和终检规范可读取；此前主要用于设计与审片，尚未系统性地把每张镜头卡转译为海螺提示词。本阶段已把它的“单镜头单动作、三秒钩子、品牌停留、先锁画面后做声音”等约束写入生产规格与审计输出。
- **Remotion**：独立Node工程和依赖已安装，当前可用于可编程包装；主成片仍由FFmpeg合成。它不会自动提升生成镜头的写实质量，价值主要在准确字幕、功能状态、Logo、CTA和可复用动画。
- **librosa**：节拍分析代码存在，但不在Python基础依赖中；缺少时安全跳过。因此当前成片不能假定已经完成音乐节拍对齐。

## 只有适配器、当前未生效

- **Real-ESRGAN**：已有可选清晰度修复节点和命令适配器，但本机未安装二进制程序，也未配置`REALESRGAN_BIN`。它只能提升通过审核画面的清晰度，不能修复商品变形、手部或人物身份。
- **RIFE**：已有补帧节点和脚本适配器，但未配置`RIFE_SCRIPT`。它只能用于通过动作审核的视频，遮挡和快速运动可能产生重影。

## 研究评测候选

- **DOVER-Mobile**：未配置`DOVER_COMMAND`，当前不执行；其研究模型和权重商用许可仍需单独复核。
- **VBench / VBench-Long**：未配置CLI，定位为离线模型基准，不适合阻塞每一次商业生产。
- **ComfyUI**：当前系统选择API路线，没有运行中的ComfyUI服务，也没有本地视频扩散模型工作流。

## 本阶段落地变化

1. 为每个镜头增加`risk_level`和`recommended_variants`，复杂手部、商品交互和跟读镜头默认标记为高风险并建议双候选。
2. 海螺提示词改为结构化段落：故事状态、唯一动作、摄影机、连续性、商品身份、物理约束、剪辑交接和禁止项。
3. 素材分析节点输出`identity-reference-manifest.json`，明确真实商品图的事实优先级；生成图不能反向覆盖商品事实。
4. 工作流升级为`frameflow-dag-v5`，旧缓存不会伪装成已经执行的新规格。

## 后续顺序

下一阶段依次实施：商品受控合成/身份图层、候选生成与盲选、屏幕功能状态后期跟踪、真实拟音与授权音乐、最终A/B样片。Real-ESRGAN和RIFE继续保持可选，只有基准测试证明净收益后才启用。
