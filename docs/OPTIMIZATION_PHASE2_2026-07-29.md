# FrameFlow 视频系统优化：第二阶段交付

## 本阶段变化

工作流节点已从“只展示状态”升级为可执行节点，并加入正式生产所需的费用确认和人工审核门禁。

## 已实现执行器

### 素材分析

- 使用本地 Ollama `qwen3-vl:4b` 分析商品、人物、场景和品牌素材。
- 生成结构化视觉档案并保存到项目产物目录。
- 不产生外部API费用。

### 关键帧生成

- 复用 Seedream 多参考图能力。
- 生成任务必须显式传入 `confirm_billable=true`。
- 云端临时URL返回后立即下载到本地项目目录。
- 节点记录模型、尝试次数、产物路径和实际费用。

### 关键帧质检

- 同时检查商品、人物、场景、故事状态和手部物理。
- 质检结果写入独立JSON报告。
- 自动质检完成后进入 `review_required`，不会自动解锁付费视频节点。
- 自动未通过时，人工覆盖必须再次明确确认。

### 首尾帧视频生成

- `VideoProvider` 增加统一的 `submit_boundary` 协议。
- Seedance 使用官方首帧/尾帧角色提交。
- MiniMax 使用官方 `first_frame_image` 和 `last_frame_image` 参数。
- 供应商不支持首尾帧时，才回退到普通参考图协议。
- 视频生成同样必须显式确认费用。

### 视频抽帧质检

- FFmpeg每两秒抽取代表帧。
- Qwen3-VL逐帧检查故事符合度、人物数量、镜头注视、文字水印和物理异常。
- 汇总平均得分与逐帧证据。
- 自动完成后进入人工审核，不直接进入最终合成。

## 新增API

```text
POST /api/projects/{project_id}/workflow/nodes/{node_id}/execute
POST /api/projects/{project_id}/workflow/nodes/{node_id}/approve
```

执行请求：

```json
{
  "confirm_billable": false,
  "provider_override": ""
}
```

审批请求：

```json
{
  "approved": true,
  "override_failed_review": false
}
```

## 防止误计费

1. 关键帧和视频生成节点标记为 `billable`。
2. 未显式确认时，后端返回 HTTP 402，任务不会被创建。
3. 前端在提交前显示本节点预计费用并要求用户确认。
4. 刷新工作流只读取状态，不会重新提交任务。
5. 每个云端任务的产物立即归档到本地，避免临时下载地址过期。
6. 局部重做只重置目标节点和下游，不重复消费已完成上游。

## 下一阶段

1. 接入旁白、字幕、环境声和声音桥正式执行器。
2. 将正式视频质检扩展为商品相似度、人物身份衰减、闪烁和运动突变评分。
3. 接入最终合成节点，只有全部镜头审核通过才能生成交付成片。
4. 增加Real-ESRGAN与RIFE可选后处理节点，并实施“先质检、后增强”规则。
5. 接入阿里云百炼万相参考生视频与视频编辑，作为多主体和局部修复路由。
