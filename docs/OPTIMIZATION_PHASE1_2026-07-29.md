# FrameFlow 视频系统优化：第一阶段交付

## 本阶段目标

将原来的线性“逐镜头调用API”升级为可观测、可缓存、可局部重做的镜头级生产工作流，同时保留已经验证过的 Seedance、MiniMax、Ollama Qwen3-VL 和 FFmpeg 能力。

## 已完成

1. 新增镜头级DAG工作流，每个节点记录依赖、状态、缓存键、尝试次数、预计/实际成本、输出和问题。
2. 建立素材分析、故事规划、共享边界关键帧、关键帧质检、视频生成、视频质检、声音时间轴和最终合成节点。
3. 局部重做节点时，仅重置该节点及其所有下游节点；上游合格产物保持完成状态。
4. 新增中国区模型能力注册表，并按人物身份、手部物理和首尾帧连续性生成逐镜头路由建议。
5. 将旧的一键渲染明确定义为“快速预览”。跳过关键帧或视频质检时，会在工作流中记录为 `skipped` 或 `review_required`，不再伪装成正式生产结果。
6. 重建前端生产控制台，提供故事、工作流、成本、重试、节点问题和模型路由页面。
7. 修复核心数据模型与前端中的中文编码问题。

```text
GET  /api/projects/{project_id}/workflow
POST /api/projects/{project_id}/workflow/nodes/{node_id}/retry
```

## 生产门禁

正式成片应满足：

```text
素材档案通过
→ 故事与分镜确认
→ 共享边界关键帧生成
→ 每张关键帧视觉质检/人工确认
→ 单镜头视频生成
→ 抽帧连续性与物理质检
→ 旁白、字幕、环境声和声音桥
→ FFmpeg确定性合成
→ 最终人工审片
```

顶部“快速预览”只为兼容已有调试方式，不应作为商业交付入口。

## 验证

- Python：12项测试通过。
- React/Vite：TypeScript检查和生产构建通过。
- Playwright：前端加载、生产工作流、模型路由和控制台错误检查通过。
- 测试未触发任何付费图像或视频生成任务。

## 下一阶段

1. 为生产工作流增加逐节点执行接口和明确的付费确认参数。
2. 将 Seedream 关键帧生成、Qwen3-VL审核和 Seedance首尾帧生成从实验脚本迁移到正式节点执行器。
3. 对 MiniMax 首尾帧、人物主体参考和万相参考生视频/视频编辑实现统一请求协议。
4. 增加视频抽帧、闪烁、运动突变和商品相似度检查。
5. 增加可选的 Real-ESRGAN修复与RIFE补帧节点；只在质检通过后启用，禁止用后处理掩盖结构错误。
6. 在同一套素材上执行小规模供应商对比，建立镜头类型到最佳模型的实测路由表。
