# 阶段 6：稳定成片基础设施

## 目标

将上一轮供应商对照实验的三个关键结论落实为不产生新增视频 API 费用的工程改造：固定关键帧成片比例、降低本地视觉模型误杀风险、为供应商失败建立可追溯的回退路径。

## 已完成改造

### 1. 精确画幅关键帧

新增 `backend/app/frame_canvas.py`。图像生成服务返回的图片即使与请求比例不符，系统也会把它规范化为项目目标画布：

| 项目比例 | 输出画布 |
| --- | --- |
| 16:9 | 1536 × 864 |
| 9:16 | 864 × 1536 |
| 1:1 | 1200 × 1200 |

规范化策略是“模糊背景 + 完整主体置中”，而不是直接裁切。它保证商品和人物不会因强制横竖裁切丢失，同时使后续图生视频始终收到正确比例的边界帧。系统保留原始生成文件，并记录规范化后的 `canvas` 与 `canvas_strategy`，便于审计。

### 2. 视觉质检由自动否决改为人工分流

`QualityDecision` 现在显式记录：

- `accept`：自动结果通过，仍按原流程等待人工确认。
- `manual_review`：发现风险，但不自动调用付费重做。
- `automatic_retry`：只有未来经过单独校准、且显式开启时才允许。

默认 `allow_automatic_paid_retry=False`。这意味着 Qwen3-VL 4B 可以继续找出商品、人物、手部和故事风险，但不会因一次低分自动消耗额度。人工确认的重试仍沿用原有“确认计费 + 重试次数与预算上限”闸门。

### 3. Seedance 到 MiniMax 的回退状态机

视频节点在重新执行时会读取上一次实际使用的供应商：若首选是 Seedance、该尝试失败、且 MiniMax 已配置，则下一次经用户确认的重试自动选择 MiniMax。操作员也可以显式指定供应商覆盖该逻辑。工作流产物会写入：

- `routing_provider`
- `fallback_provider`
- `fallback_applied`

该机制只决定下一次重试的路由，不会在后台自行发起付费任务。
