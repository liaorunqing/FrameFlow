# FrameFlow 第三阶段优化记录（2026-07-29）

## 阶段目标

本阶段把系统从“能够生成分镜片段”推进到“能够在人工审核后稳定交付成片”。重点不是继续堆叠生成模型，而是补齐音频时间轴、字幕、声音桥、最终合成、可选画质增强和旧工作流迁移。

## 已完成能力

### 1. 本地旁白与字幕时间轴

- 根据故事镜头生成逐镜头旁白 cue 和 SRT 字幕。
- 时间轴总时长严格对齐项目时长。
- Windows 本地语音优先，失败时可尝试本地 `edge-tts`。
- 默认禁止静默回退到 MiniMax 付费语音，避免测试阶段产生未确认费用。
- 输出 `narration.wav`、`subtitles.srt` 和 `audio-timeline.json`。

### 2. 最终成片门控

`final-compose` 只有在以下条件全部满足后才进入可执行状态：

1. 所有关键帧完成自动质检并通过人工审核；
2. 所有视频镜头完成连贯性、物理合理性与商品一致性审核；
3. 旁白和字幕时间轴生成完成。

这样可以避免把错误镜头提前烘焙进最终成片，也便于只重做失败镜头。

### 3. FFmpeg 交付合成

- 统一画幅、帧率和编码格式；
- 连续旁白作为跨镜头声音桥；
- 添加轻量环境底噪，降低镜头切换的听觉断裂；
- 烧录字幕；
- 支持 Logo 与 CTA 片尾卡；
- 输出适合网页预览和交付的 H.264/AAC MP4。

### 4. 可选增强适配器

系统已经加入 Real-ESRGAN 与 RIFE 的工具探测和执行适配器，但默认跳过：

- Real-ESRGAN 只负责通过审核后的清晰度修复，不能修复人物身份、手部或商品结构错误；
- RIFE 只负责通过动作审核后的补帧，快速运动和遮挡场景可能出现重影；
- 两者只有在本机安装并配置后才允许执行，不会自动下载大型模型。

当前机器探测结果：FFmpeg 可用，Real-ESRGAN 和 RIFE 尚未安装。

### 5. 工作流 v3 无损迁移

旧项目访问工作流时会自动迁移到 `frameflow-dag-v3`。缓存指纹未变化的节点会保留原有完成状态、审核结果、尝试次数、实际成本和产物；新节点会按默认状态补入，避免旧项目从头生成。

## 下一阶段建议

下一阶段应优先进行“生成质量基准与自动修复策略”：

1. 建立不同镜头类型的供应商基准集，分别记录人物一致性、商品一致性、动作物理、首尾帧衔接、成本和成功率；
2. 将视觉质检结果映射为局部修复动作，例如重写提示词、降低动作复杂度、更换生成模型或退回关键帧；
3. 增加镜头级成本预算和最大重试预算，超过阈值时等待人工决策；
4. 在 30 秒流程稳定后，用相同故事段落结构扩展到 45 秒和 60 秒，而不是简单增加镜头数量；
5. Real-ESRGAN 和 RIFE 仅在基准测试证明收益高于伪影风险后再正式启用。
